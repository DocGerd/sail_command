A route calculation that runs out of time now says so. The solver is given a wall-clock budget for the whole plan and stops honestly when it is spent, reporting that the search was cut short — explicitly not that no route exists — instead of the previous "Route planning failed unexpectedly. Try again; if it keeps happening, reload the app.", which named neither the cause nor anything the skipper could act on. Adding a via point to an existing route, and "reroute from here" in Live view, now report the real cause of a routing failure too (a timeout, a crashed engine, a failed save) rather than collapsing every one of them onto that same generic message, and they release the abandoned routing worker so a retry starts from a clean engine instead of stacking onto a busy one.
